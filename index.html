tiny-hnsw In progress

Rust · HNSW · Qdrant · LanceDB · source

HNSW (Hierarchical Navigable Small World) is the graph algorithm behind vector databases like Qdrant and Milvus. It searches a sparse top layer first, then drops into denser layers beneath it. I implemented it from scratch in Rust, with multi-layer graph construction, greedy descent, beam-search retrieval, diversity-pruning neighbour selection and tombstone-based soft deletion.

I'm now integrating Qdrant with LanceDB (columnar vector storage) to build a hybrid search pipeline: low-latency candidate generation, then cost-efficient filtering and re-ranking at scale. Click the diagram to place a query and watch the search descend.

LMAX-rs

Rust · lock-free ring buffer · order book · source

A matching engine keeps resting orders sorted by price and arrival time, and crosses incoming orders against them. Mine started as a single-threaded design and evolved into a lock-free, ring-buffer pipeline. Its stages (unmarshaller, journal, replicator and business logic) are coordinated by atomic sequence numbers, with no locks on the hot path. The order book gives O(1) best bid/ask lookup and constant-time cancellation.

Neon architecture study In progress

Learning project · PostgreSQL · log-structured storage

I'm studying how Neon separates Postgres compute from storage, and re-implementing parts of that design to understand it properly. There is no complete write-up yet. Below is my current understanding, plus a simplified model I built to check it.

Neon runs ordinary Postgres but replaces the disk underneath it. The compute node keeps no durable data, so it can stop, restart or be cloned in seconds. Everything it needs lives in a separate storage system with three parts.

Writes. Postgres streams its write-ahead log (WAL) to the safekeepers. A change is durable once a majority of them have it. The pageserver then ingests the WAL and stores it as immutable layer files, which are uploaded to object storage.

Reads. When Postgres needs a page, it asks the pageserver for that page at a specific log position (LSN). The pageserver finds the newest full copy of the page, an image layer, then replays any later changes stored in delta layers. Layers are never overwritten, so this works like a log-structured merge tree.

Pageserver layer map

Compaction. Reading a page that has many deltas stacked above its last image means replaying a lot of WAL. Compaction writes new image layers so future reads start closer to the present. Older layers are kept until they pass the retention window, which is what allows point-in-time restore.

Branching. Because layers are immutable, a branch is a new timeline that points at its parent's layers up to the branch point and stores only its own new writes. Creating one copies no data, whatever the database size.
